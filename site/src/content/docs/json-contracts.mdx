`vimanam diff --format json` defaults to neutral contract v2 (`--contract 2`), sharing one machine-readable JSON envelope across OpenAPI, Protocol Buffers, and GraphQL. Legacy OpenAPI consumers can pass `--contract 1` to keep the unchanged v1 schema and `vc1_` identifiers.

## Envelope structure

```json
{
  "schema_version": 2,
  "generator": { "name": "vimanam", "version": "2.2.0" },
  "old": {
    "file_sha256": "<64 lowercase hex>",
    "contract": { "format": "openapi", "title": "Widgets API", "version": "1.0.0", "entities": [] }
  },
  "new": {
    "file_sha256": "<64 lowercase hex>",
    "contract": { "format": "openapi", "title": "Widgets API", "version": "1.1.0", "entities": [] }
  },
  "summary": {
    "operations_added": 0,
    "operations_removed": 0,
    "operations_changed": 1,
    "breaking": 1,
    "non_breaking": 2,
    "review": 1
  },
  "changes": [
    {
      "id": "vc2_<64 lowercase hex>",
      "subject": "ve2_<64 lowercase hex>",
      "kind": "field_type_changed",
      "severity": "breaking",
      "impacts": ["wire", "source"],
      "native": { "format": "protobuf", "full_name": "example.v1.Order.id", "number": 1 },
      "native_kind": "FIELD_SAME_TYPE",
      "details": {}
    }
  ]
}
```

`deltas` is included only when you pass `--report`; otherwise the key is omitted. All map keys — including flattened OpenAPI `extensions` — serialize deterministically.

## Omitting the full surfaces (`--omit-surfaces`)

`old.contract` and `new.contract` hold every entity of both specs, so on a large spec they are nearly all of the document. CI gates, PR bots and coding agents that read only `summary` and `changes` can pass `--omit-surfaces`:

```bash
vimanam diff old.json new.json --format json --omit-surfaces --fail-on-breaking
```

```json
{
  "schema_version": 2,
  "generator": { "name": "vimanam", "version": "2.2.0" },
  "surfaces_omitted": true,
  "old": { "file_sha256": "<64 lowercase hex>" },
  "new": { "file_sha256": "<64 lowercase hex>" },
  "summary": { "operations_added": 0, "operations_removed": 0, "operations_changed": 1, "breaking": 1, "non_breaking": 2, "review": 1 },
  "changes": [ … ]
}
```

- Each side keeps only `file_sha256`; `surfaces_omitted: true` marks the shape and never appears in the default output, which stays byte-identical.
- `summary`, `changes` (every `vc2_` and `ve2_` ID), `deltas` and the `--fail-on-breaking` / `--breaking` exit codes are identical to the run without the flag, for OpenAPI, Protobuf and GraphQL, from files or Git refs.
- Without the surfaces, a `ve2_` ID can no longer be looked up for its entity's name, parent or attributes. Each change's `native` location and `native_kind` already say where the change is; to join IDs against full entity records, run again without the flag (IDs are stable across runs).

<Aside type="caution" title="v2 JSON only">
  `--omit-surfaces` requires `--format json` with contract v2. With Markdown output or `--contract 1`, neither of which has surfaces, it exits with status `1` before creating any output file.
</Aside>

## Stable entity and change identities

- **Entity IDs (`ve2_`)**: `"ve2_" + SHA-256` of canonical JSON `{v: 2, format, kind, coordinate}` with keys sorted recursively. Descriptions, comments, generator versions, and declaration order never alter an entity ID.
- **Change IDs (`vc2_`)**: `"vc2_" + SHA-256` of canonical JSON `{v: 2, subject, kind, details}`. Severity labels, impact dimensions, `uses`, file paths, raw file hashes, and generator versions stay outside the hash so suppression lists keyed on `vc2_` IDs remain stable across policy updates.
- **OpenAPI media types**: a request body or response with several media types is compared per media type (exact keys). A media type one side lacks is `argument_removed`/`argument_added` on that media type's body argument, or `result_removed`/`result_added` on the status's result, with `media_type` in `details` (native kinds `request_media_type_removed`, `response_media_type_added`, ...). A schema change of one media type adds `media_type` to `details`. Specs whose bodies and responses keep one media type get exactly the IDs they had before.
- **Shared OpenAPI components**: a change inside a `$ref` target is one `component_schema_changed` fact per usage direction, with the named type as `subject`, `component` and `direction` in `details`, and the reaching argument/result entity IDs in `uses`. Because `uses` is not hashed, the ID does not change when another operation starts using the component. Since 2.3.0 these replace the per-operation facts earlier releases emitted for every reference path.

## Cross-format surface mapping

| Neutral entity | OpenAPI | Protobuf / gRPC | GraphQL |
|---|---|---|---|
| `service` | Declared or inferred tag | Fully qualified service | `Query`, `Mutation`, `Subscription` root |
| `operation` | `METHOD` + exact path | Fully qualified RPC | Root schema field (`Query.user`) |
| `argument` | Parameter or synthetic body | Request message reference | Field argument (`Query.user(id:)`) |
| `result` | Response status + first schema (other media types in change `details`) | Output message reference | Root return type |
| `type` | Component or definition schema | Message, enum, nested type, file, package | Object, interface, input, enum, union, scalar |
| `field` | Property or composition member | Message field or `oneof` member | Object, interface, or input field |
| `value` | Canonical JSON enum member | Enum FQN + number + name | Enum value coordinate (`Role.ADMIN`) |

## Pagination inference across formats

Pagination changes emit a `pagination_changed` fact carrying structured evidence and confidence (`declared` > `corroborated` > `inferred`):

- **OpenAPI** *(always `review`)*: combines query controls (`page`, `size`, `pageToken`, `cursor`, `limit`, `offset`) with a 2xx response containing an array property and a continuation field (top-level or one level deep, plus optional end-of-results flags such as `has_more` or `is_last`).
- **Protobuf** *(always `review`)*: matches AIP-158 RPCs with `page_size` and `page_token` request fields and `next_page_token` plus repeated items in the response.
- **GraphQL** *(`breaking` when switching between list and connection; `review` for control edits)*: matches Relay `edges { node }` or `nodes` connections with `pageInfo` and `first`/`after` or `last`/`before`.

## Legacy OpenAPI v1 contract (`--contract 1`)

Pass `--contract 1` when an existing OpenAPI script expects the v1 schema (`schema_version: 1`, `vc1_` IDs, and exact path matching without move pairing). v1 compares media types the same way: a media type one side lacks is a `request_media_type_removed`/`_added` or `response_media_type_removed`/`_added` record (details `media_type`, plus `status` for responses), and a schema record of a body or response compared per media type has `media_type` in its details (so its `vc1_` ID differs from the single-media one):

```bash
vimanam diff old.json new.json --format json --contract 1 --report
```

<Aside type="caution" title="Contract v1 is OpenAPI-only">
  Protobuf and GraphQL inputs require contract v2 and exit with status `1` before creating any output file if `--contract 1` is passed.
</Aside>
