This page is a snapshot of the 2.3.0 release, measured on 2026-11-27. Both release binaries ran on the same machine in the same session. The raw captures are:

- [`scripts/benchmark-v23-results.json`](https://github.com/noemaforge/vimanam/blob/main/scripts/benchmark-v23-results.json): `hyperfine 2.0.0` medians, Q1–Q3 interquartile ranges (IQRs), peak RSS and CPU instruction counts.
- [`scripts/benchmark-diff-refs-v23-results.json`](https://github.com/noemaforge/vimanam/blob/main/scripts/benchmark-diff-refs-v23-results.json): `vimanam diff` timings on OpenAI and Stripe, `5` runs each, with 2.2.0 stopped after `30 s`.

In short, `diff` is faster in every format, and renders do the same work within a few percent. On 15 consecutive Stripe releases, 2.2.0 didn't finish any diff within `30 s`, and 2.3.0 finished each one in under `1.6 s`.

## Diff verdict changes

On OpenAI `a01e367..373f26a`, 2.3.0 reports `4` breaking findings, all real. 2.2.0 reported `62`, of which `4` were real.

| Finding group | 2.2.0 | 2.3.0 | What changed |
|---|---:|---:|---|
| Response `enum: [v]` → `const: v` rewrite | `49` breaking | `0` breaking | Removing a value from a response enum is now non-breaking ([#169](https://github.com/noemaforge/vimanam/issues/169)) |
| Request `enum: [v]` → `const: v` rewrite | `9` breaking | `0` breaking | Dropping a whole request `enum` is now one non-breaking `/enum` change, and adding `const` is Review |
| `notification_channel` `anyOf` edit on two spend-limit endpoints | `4` breaking | `4` breaking | Unchanged: `2` `field_required_changed` and `2` `field_type_changed` |

The v2 JSON summary goes from `62` breaking, `12` non-breaking and `134` review to `4`, `17` and `133`. Vimanam still doesn't treat `enum: [v]` and `const: v` as equal ([#167](https://github.com/noemaforge/vimanam/issues/167)). It avoids the false alarm here only because of the two rules in the table.

Other 2.3.0 changes that affect comparisons with other tools:

- Changing an RPC between unary and streaming is now wire-breaking ([#153](https://github.com/noemaforge/vimanam/issues/153)). The Protobuf smoke test now matches `buf` WIRE on all 8 cases.
- A `$ref` retargeted to a differently named component is now a Review change, even when the two components have the same shape.
- 2.3.0 compares every media type of a request body or response, not only the first ([#154](https://github.com/noemaforge/vimanam/issues/154)).

For accuracy against `oasdiff`, `graphql-inspector` and `buf` on real release histories, see [v2.3.0 vs external tools](/vimanam/benchmarks/v2-3-external-tools/#accuracy-on-real-release-histories).

Render times are unchanged within noise. Instruction counts stay within ±3% for OpenAPI and Protobuf. GraphQL renders do 4% to 7% more work, which matches 2.3.0's new duplicate-member checks ([#163](https://github.com/noemaforge/vimanam/issues/163)) and argument input-type expansion ([#170](https://github.com/noemaforge/vimanam/issues/170)).

Several small wall-time differences have disjoint IQRs but didn't hold up on a 30-run recheck:

- GitHub GraphQL SDL: `73.8 ± 18.4 ms` (2.2.0) against `75.6 ± 10.1 ms` (2.3.0).
- gRPC Health `.proto`: `9.5 ± 1.0 ms` against `9.8 ± 0.8 ms`, where the 10-run medians showed `7.3` against `11.0 ms`.

## Measurement conditions

<Aside type="caution" title="The machine wasn't idle">
  The load average was about 6 to 19 on 12 cores during these runs. Wall times and IQRs include that noise. CPU instruction counts don't depend on load, so treat them as the more reliable column.
</Aside>

| Item | Value |
|---|---|
| Machine | Apple Silicon, `macOS 26.7.3 arm64`, Apple Git `2.54.0` |
| Timing harness | `hyperfine 2.0.0` for renders and GraphQL/Protobuf diffs; `scripts/benchmark-diff-refs.py` (median and range, peak RSS from `wait4`) for OpenAI and Stripe diffs |
| Run counts | `10` per render and SpaceX diff, `5` per GitHub Git-ref diff and per OpenAI/Stripe mode, `6` for OpenTelemetry Git-ref, `3` for the 200-proto repo |
| 2.2.0 binary | SHA-256 `ed253315…`, `9,731,360` bytes |
| 2.3.0 binary | SHA-256 `f02778f4…`, `10,324,976` bytes (`+593,616` bytes, `+6.1%`) |
| Timeout | `30 s` for 2.2.0 on Stripe; the slowest 2.3.0 Stripe case took `1,518.7 ms` |

The 30-run rechecks above were run by hand after the main capture and aren't in the results files.
