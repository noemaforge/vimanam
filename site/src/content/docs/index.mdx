## How the pipeline works

Vimanam parses each input format into a shared intermediate representation for rendering, and into a neutral contract surface for semantic comparisons. Output order stays byte-deterministic so generated docs diff cleanly in Git and preserve LLM prompt caches.

## Why teams use Vimanam

<div class="vim-pillars not-content">
  <div class="vim-pillar">
    <h3>Bounded context for coding agents</h3>
    <p>Large OpenAPI and GraphQL specs consume hundreds of thousands of tokens. Use <code>--stats</code>, <code>--costs</code>, <code>--schema-field</code>, and <code>--output-mode skill</code> to give agents only the operations and subtrees a task needs.</p>
  </div>
  <div class="vim-pillar">
    <h3>Pure-Rust parsing with no toolchains</h3>
    <p>Compile <code>.proto</code> files with Google well-known imports via <code>protox</code> without installing <code>protoc</code>, parse YAML 1.2 without C libraries via <code>serde-saphyr</code>, and merge multi-file GraphQL SDL with <code>apollo-parser</code>.</p>
  </div>
  <div class="vim-pillar">
    <h3>Stable breaking-change CI gates</h3>
    <p>Compare files or Git commits directly. Every change receives a SHA-256 <code>vc2_</code> identifier and directional verdict so CI blocks breaking edits with exit code <code>3</code> while keeping suppression lists stable.</p>
  </div>
</div>
